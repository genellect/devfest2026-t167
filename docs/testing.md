# テスト

`bash scripts/dev.sh check` が、CI と同じ検査を手元で実行する。GitHub Actions は PR と `main` への push のたびに同じ検査を実行する。概要は [README](../README.md#テスト) にある。

## 検査の一覧

| 検査 | 内容 |
|---|---|
| lint・型・ビルド | web と api |
| 単体テスト | 表示の整形、4つの指標の計算、起動時の環境変数（空・未設定で止まる）、Gemini への生成の設定（思考レベル LOW）、録音の分析の出力の切り詰めと時刻の形 |
| Rules | 生徒・教師・学校管理者・失効/refresh想定・匿名・未ログインすべてについて、FirestoreとStorageの直接読み書き/一覧を拒否 |
| API の結合 | エンドポイントごとの認可（`401`・`403`）、フェーズ（`409`）、分析の排他と30秒制限（`409`・`429`）、Gemini の失敗（`503`）、グループごとの進行と結果、録音の同意・形式・長さ・大きさ・1回だけの分析・30秒あけた再送・3回までの上限、本文をログ/エラーへ出さないこと、同時移動/開始、終了後の送信と結果保存の拒否、合意分析の排他と期限切れ後の古い結果の破棄 |
| E2E | スマホ幅で、教員の作成画面から1本の流れの通し（事前意見 → 開始 → 発言メモ → 未検討論点の提案と承認 → 終了 → 結論の一文 → 理解のずれと指標。意見と一文の本文が教員に出ないこと）、未準備の学生を外して開始し、同意を取り消した録音を送らないこと、参加コードからの参加と非公開意見の提出、QR の URL からログイン後にそのまま参加、アプリ内カメラでの QR の読み取り（擬似カメラ）、数字だけの入力、誤ったコードのエラー、ログイン後の振り分け（教員は教員のホーム、学生は参加コードの入力）と、教員でない利用者が画面と API のどちらからも作成できないこと、ホーム・参加・作成・設定・使い方の画面が横にはみ出さないことと、左上のロゴ（Topos）と右上の設定の行き先、未検討の論点の「見送る」で付箋が消えて学生に届かないこと、投影画面（教員だけが開け、全員に表示した問いかけだけを映し、見送った提案と事前意見の本文は映さない）、録音の同意から分析の結果まで（擬似マイク）、分析の失敗（`503`）と、途中で止まった分析の期限切れのあとのやり直し、ホーム画面に追加するためのマニフェストとアイコン（PWA） |
| 提出スクリプト | 秘密情報の検出と、検査前に提出先を変えないこと |
| 開発の入口 | CI の変更判定、`dev.sh pr` の PR 作成と承諾前の auto-merge の防止（Rules・ワークフロー・構築スクリプト・`.claude/`・`.codex/` を変えた PR には承諾後も付けない）、`serve` を停止するときの子プロセスの終了、不正オフセット・既存サーバー保護 |
| 設定の受け渡し | GitHub の Variables の一覧の一致とデプロイ前の検査（任意の `API_MIN_INSTANCES` は 0〜2 だけを通し、デプロイが最小インスタンス数を直書きしないこと）、文書だけの push でデプロイしない条件が CI の変更判定と同じこと、デプロイ後の本番の URL の確認があること、API が受け取る環境変数、クラウドのログインのプロジェクト、gcloud・ADC がないときの案内、プレビューとメンバーの権限の設定 |
| Rules の配備 | Firebase登録バケットの全ページ取得、登録なし、権限・通信・応答異常時の停止、計画モード、一時設定の削除。実クラウドへ配備しない |
| 教員の権限の付与 | 対象を明示しないと拒否すること、ほかの claim を残すこと、以前のトークンを失効させること、引数の内容をログに出さないこと（gcloud は偽物） |
| API のイメージと起動順 | 本番の API イメージに音声処理と固定版のモデルを入れ、秘密を持ち込まないこと、API の応答を待ってから画面を起動すること、デモが通常のトラフィックを変えないこと |

## 実行のしかた

Rules・API の結合・E2E は、Auth・Firestore・Storage のエミュレータと Gemini のモックで動かす。GCP の認証情報は使わない。

API のカバレッジ（行・文85%、分岐80%、関数90%以上）を下回ると失敗する。進行規則の変異検査で、境界を壊した変更をすべて検出することを確かめる。30人・6グループの同時提出を3回行い、応答の p95 が1秒未満であることを確かめる（エミュレータ上の測定）。

`web` の `typecheck` はアプリと E2E を別の設定で検査する。App Hosting のアプリビルドには `web/` 外のエミュレータ用補助ファイルを含めず、E2E の型検査はリポジトリ全体を取得する CI で行う。

品質検査の契約・制限・旧形式との互換性は [backend-contract](backend-contract.md) にある。`T167_TEST_PORT_OFFSET=10000 bash scripts/dev.sh check` で、起動中のプレビューとポート・DB 名を分けて検査できる。使用中のポートは拒否し、他のサーバーを再利用しない。
