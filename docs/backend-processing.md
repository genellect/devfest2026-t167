# 音声処理・分析・保存期限

音声登録・録音・共有資料の既存導線へ、短い音声区間の文字起こしと永続分析ジョブを接続する。モデルは既存のVertex AI Gemini、global、LOWを維持する。外部の文字起こしAPIや新しいAPIキーは追加しない。Google認証・Vertexの資格情報は既存の設定を使い、キーやトークンは保存・配信しない。

## 音声から分析まで

同じマイクのPCMを話者識別（1秒）と文字起こし（10秒、停止時は残り）に渡す。文字起こしは1〜20秒の16kHz mono PCM16を受け付ける。captureごとの連番・音声指紋・処理leaseで順序と冪等性を守る。短い区間はGeminiで忠実に文字起こしし、無音・聞き取れない区間・録音時間外の出力を採用しない。

原音はサーバーに保存しない。端末のMediaRecorderの録音は、文字起こしや話者識別が失敗しても継続する。文字起こしは同じ区間を最大3回再送し、接続不能・待ち行列過多では停止して元の録音による終了後分析へ戻す。終了後の録音送信も、一時的な通信・混雑・503の失敗時は同じBlobを最大3回まで自動再送し、手動再送も維持する。サーバーが音声を受けてから文字起こし保存前に落ちた場合は、端末が同じ音声を再送する必要がある。端末も閉じた場合の自動復旧を保証しない。

話者イベントと時刻の重なりを照合し、一人の既知話者が十分に覆った区間だけを本人へ対応付ける。既知の割合80%以上、発言時間の60%以上が条件。これは推定であり、混ざった声や短い相づちの完全分離ではない。匿名話者・複数話者・不明区間は個人の振り返りへ渡さない。

## 分析ジョブ

`processingJobs`に文字起こしから作った非公開の入力を保持する。ジョブIDは対象・入力のハッシュ。追加の文字起こしベースの分析入力は、対象の最新200発言までとする。録音全体を渡す既存のグループ録音分析とは区別し、追加の振り返りを全発言の完全な評価とは扱わない。leaseは60秒、最大3試行。同じプロセス内ではセッション単位で短いDB処理を直列化し、音声更新と終了処理のロック競合を抑える。モデル呼び出しは直列化の外で行い、別プロセスとの整合性はFirestoreのトランザクションで維持する。途中で止まったジョブはlease失効後に回収し、終了済みジョブは再処理しない。新しい入力が来た対象は最新のジョブだけを結果へ採用する。音声がない終了済みセッションには自動分析ジョブを作らず、根拠が空の本人結果はAIを呼ばず空の結果として返す。成功時にジョブの入力本文を削除する。失敗した最新ジョブはHost画面から明示再試行できる。

- 議論中：グループ別の未検討論点と内容の振り返り。通常30秒以上の間隔で更新。未検討論点はHostの承認後だけ参加者へ表示する。
- 終了後：グループ・セッション全体・本人の振り返り。観察と次に試す行動を分け、各項目を実在する発言IDに限定する。根拠がない場合は空の結果。人格・能力・意欲・成績を評価しない。
- 発言率：話者識別の推定発話時間を使用し、話者不明を分母に残す。無音のみならデータなし。既存のメッセージ件数に基づく指標とは別のAPI・表示とする。

未指定または`recordingMode: auto`では、開始時に2名以上の全員が個人端末なら`personal`、それ以外は`single`に決定する。Hostの明示した方式や代表担当を優先する。`personal`では各自端末のleaseを独立させる。同じ秒・同じ話者の発話時間は最大値で統合し、重なった同一文の文字起こしを統合する。複数マイクの時計・遅延・表記揺れにより、完全な音響重複除去ではない。匿名区分上限はグループ参加上限に合わせ100。100人の実環境での識別精度を保証する値ではない。

各自端末モードの終了録音は、本人ごとの`recordingUploads/{uid}`で受領・排他・再送を管理する。他端末の分析完了では本人の録音を削除しない。非公開の受領記録に分析結果だけを保存し、原音は保存しない。グループの`flow-gN`は分析済み端末数と端末ごとの要約を表示する。別々の録音を連続した1本の時系列として合成せず、表示時刻は各端末の録音開始からの目安と明示する。発言率と文字起こしの重複推定とは別の集約である。

## 認可と保存期限

ブラウザのFirestore/Storage直接アクセスは既存のRulesで拒否し、APIで独自ログインセッション・現在の所属・セッション内ロール・グループ・公開設定を検査する。文字起こし処理後も再検証し、途中で除外・ログイン失効・削除された場合に結果を保存しない。内部ジョブ・音声特徴・GoogleトークンをSSEへ追加しない。自動音声送信・分析の定期実行でログインの最終利用時刻を延長しない。

期限の既定値は`api/src/processing-types.ts`の`RETENTION`へ集約する。

| 対象 | 期限・削除 |
|---|---|
| ディスカッションと配下の文字起こし・分析・資料 | 新フローは作成から30日。旧形式の既存データは自動削除対象外。Hostは終了後に明示削除も可能 |
| アカウントに保存した声の特徴 | 最終登録・利用から90日。本人による即時削除も維持 |
| 端末の原音 | 送信成功後、または議論終了から5分後に削除 |
| 失効済み認証セッション・監査記録 | 既存のdeleteAtに従って削除 |

APIプロセスのワーカーが10秒ごとに20セッション・20ユーザーずつ巡回する。時間切れの確定、分析ジョブの回収、保存期限処理を行う。デモの名前空間外を検索するcollectionGroupは使わない。削除開始済みセッションは受付を閉じ、参加コードとユーザー側の参照も削除する。

ブラウザを閉じている間は端末の物理削除を実行できない。保存済みの期限は次の読み込み時に適用し、端末管理画面はサーバーへ受付期限を再照会する。APIプロセスが停止・0台の間もワーカーは動かない。クラウドで期限を継続保証するには、常時稼働CPUまたは同じ処理を定期起動する運用設定が別途必要。この変更では本番の設定やデプロイを変更しない。

## API

| API | アクセス |
|---|---|
| POST /rooms/:id/transcripts/audio?sequence=N&capture=UUID | 議論中〜終了5分以内のParticipant、許可された録音端末 |
| GET /rooms/:id/transcripts?group=N | Host。Participantは終了後、公開済みの所属グループだけ |
| GET /rooms/:id/speaking-metrics?group=N | Host。Participantは所属グループかつHostが発言情報を公開した場合 |
| POST /rooms/:id/processing/:jobId/retry | Hostのみ、失敗済みの最新ジョブ |
| POST /rooms/:id/processing/run・GET /rooms/:id/processing | Hostのみ。状態一覧に本文は含めない |
| POST /rooms/:id/feedback | 終了後の本人、またはHostによる有効な参加者の指定 |
| GET /rooms/:id/feedback/:uid | Host、または公開済み結果の本人のみ |
| POST /rooms/:id/review | Hostによるセッション全体の振り返り再要求 |
| POST /rooms/:id/delete | Host、終了済み、confirm:true |
| POST /recordings/retention | 本人の保存録音のroomIds（最大100）。期限だけを返す |

Drive・Classroomは[Workspace連携](workspace-integrations.md)を参照。実GoogleのOAuth同意・学校の管理設定・実教室での音声精度は、エミュレータ試験の成功と区別する。

## 検証

通常の規定検査は`bash scripts/dev.sh check`。Classroom・Driveの最新実装と共通UIへ統合した状態で実行する。個人音声登録必須・共有端末匿名・事前意見入力省略・録音成功後削除の現行フローを維持する。DriveのGET/POSTとClassroomのルートを重複登録しない。

`speaker-check`は合成音声2種類による実モデルと補助試験、`real-check`は使用許可のある公開音声によるブラウザ録音・実モデル・実Gemini・結果表示を扱う。[実Google/公開音声検証](real-google-testing.md)を参照。実OAuth/実Drive/学校のClassroom・物理端末・クラウドの常時稼働は別の確認項目とする。

話者照合は直近1〜3秒のPCMを毎秒受け付け、VADと発言時間は末尾1秒だけで計算する。1秒だけでは曖昧な場合に限り、現在の最上位候補と文脈の候補が一致したときに照合を補う。同点・別の候補・特徴を取得できない区間は不明のままとし、閾値を下げない。照合用の履歴は端末のメモリ内の直近3秒分に限り、停止時に消去する。送信待ちのPCMは各送信の完了・失敗・停止時に消去し、サーバーでは保存しない。

ホストの開始画面は開始APIの成功応答を確認した時点で議論表示へ進み、購読を張り直して最新状態を取得する。接続を張り直す間は既存の画面を維持し、録音コンポーネントを空の配信状態で取り外さない。
