# 本番の URL で通しを確かめる手順

本番反映のあとに、人が本番の URL で確かめる手順。エージェントは次の3つを確かめられないので、この手順で人が確かめる。

- 本物の Google アカウントでのログイン
- 本物の Gemini の出力を画面で見ること
- 実機とプロジェクターでの表示

結果は PR か依頼者に送り、直す点があればエージェントに渡す。README の「テスト」の節に書く本番の結果も、この手順で確かめたものだけにする。

- 本番の URL：https://web--devfest2026-t167.asia-east1.hosted.app
- 教師権限の付け方は、[MVPロール設計](mvp-roles.md)の「本番で教師権限を付ける手順」にある。権限を付けたあとは、本人がログインし直す。
- テーマと意見は架空のものを使う。本物の生徒の情報や、個人を特定できる内容は入力しない。

## 1. 教員が議論を作り、本物の Gemini で最後まで通す

### 準備するもの

| 役割 | 端末 | アカウント |
|---|---|---|
| 教員 | PC（できればプロジェクターにつなぐ） | 教師権限を付けたアカウント |
| 学生（3人以上） | スマホ | 教員とは別の Google アカウント（1人1台） |

### 教員：議論を作り、教室に映す

1. PC で本番の URL を開き、「Googleでログイン」を押す。
2. **確かめる①**：「教員のホーム」が開き、右上に「議論を作る」が出る。
   - 参加コードの入力画面が開いたら、教師権限が効いていない。ログアウトして、ログインし直す。
3. 「議論を作る」を押し、テーマ（例：大学の課題提出でAIの利用を認めるべきか）を入れて「作成する」を押す。
4. 上の帯の「投影画面」を押す。別のタブで黒板の色の投影画面が開くので、プロジェクターに映す。
5. **確かめる②**：投影画面に、大きな6桁の参加コード・QR コード・参加人数が出る。

### 学生：参加して意見を出す（全員）

6. スマホで本番の URL を開き、「Googleでログイン」を押す。
7. 参加コードの6マスに数字を入れて「参加する」を押す。QR を読む場合は「カメラで読み取る」を押す。
8. 「自分の端末で参加」を選び、表示名を入れて「表示名を保存して進む」を押す。
9. 声の登録は「声を登録する」（画面の文を9秒読む）か「あとで登録する」を押す。
10. 意見を2〜3文で書いて「提出する」を押す。学生どうしで、わざと違う観点にする。

### 教員：議論を始めて、まだ話されていない論点を出す

11. 操作画面で、参加と事前意見の数が人数分になったことを確かめて、「議論を開始」を押す。
12. 学生は1〜2分話し合い、スマホ右上の設定を開き、発言メモに出た意見を書いて「メモを共有する」を押す。
13. 教員の操作画面で「分析を更新」を押す。新しいメモが届けば、前の分析から60秒たつと自動でも探す。
14. **確かめる③（本物の Gemini）**：Geminiアイコン付きの分析欄で、黄色の「不足している観点」と青色の「新しい切り口」を確認する。共有メモがあるグループには議論の軸・主な論点も出る。
    - 上の帯の「デモデータ」とGemini分析欄の「デモ」の札がない（あればモックで動いている）。
    - 学生の意見の本文が、そのまま出ていない。
    - 言い換えが自然か。
15. 1つの付箋で「全員に表示する」を押す。**確かめる④**：学生のスマホ右上の設定に件数が付き、設定内と投影画面に問いかけが表示される。
16. 別の付箋で「見送る」を押す。**確かめる⑤**：その付箋が消え、学生のスマホにも投影画面にも出ない。

### 終わって、合意のずれを見る

17. 教員が「議論を終える」→「終えて結果を見る」を押す。
18. 学生は「結論を自分の言葉で書く」に結論を一文で書き、納得の度合いを1〜5で選んで「提出する」を押す。学生どうしで、書き方を少し変える。
19. 教員の画面に「グループ1：結果あり」が出たら、「結果をまとめる」を押す。
20. **確かめる⑥（本物の Gemini）**：
    - 教員の画面：「合意の中身」に、理解のまとまりが色の違う付箋で出る（例：同じ結論でも、理解が2通りに分かれました）。指標も出る。
    - 学生の意見や一文の本文が、教員の画面にそのまま出ていない。
21. **確かめる⑦**：学生のスマホの結果画面に、自分が書いた理解と、グループの理解のまとまりの付箋が出る。誰がどれを書いたかは出ない。

### 送るもの

- 確かめる①〜⑦のそれぞれが、うまくいったかどうか。
- うまくいかなかった画面のスクリーンショットと、出たエラーの文言。スクリーンショットに、本物のメールアドレスや個人の情報を写さない。
- Gemini の論点や結果の文章で、不自然だったところ。

## 2. 実機とプロジェクター

1 の流れの途中で確かめる。

| 端末 | 見るところ |
|---|---|
| iPhone（Safari）・Android（Chrome） | <ul><li>ログイン画面</li><li>参加コードの6マス（数字のキーが出るか）</li><li>「カメラで読み取る」で QR が読めるか</li><li>議論中の発言メモと黄色の問いかけ</li><li>結論の1〜5の目盛り</li><li>結果画面</li><li>どの画面も横にスクロールしないこと</li></ul> |
| プロジェクター | 投影画面で、次の3つを確かめる。<ul><li>教室の一番後ろの席から6桁の数字が読めるか</li><li>スマホで QR が読めるか</li><li>議論中の時間と問いかけが読めるか</li></ul>「全画面にする」のボタンで全画面になるか（ならなければブラウザの全画面を使う） |
| ホーム画面への追加 | iPhone は共有ボタン →「ホーム画面に追加」、Android はメニュー →「ホーム画面に追加」。<ul><li>アイコンの名前が「Topos」になるか</li><li>追加したアイコンから開くと、ブラウザの枠なしで開くか</li></ul> |
| 手動の確認 | <ul><li>議論中に機内モードにして戻したとき、画面が追いつくか</li><li>再読み込みしたとき、同じ部屋に戻れるか</li><li>声を登録した学生が、開始後も同じ参加コードで部屋に戻れるか</li><li>議論の開始後に、別のスマホから参加コードで途中参加でき、表示名を入れるとそのまま議論の画面に進むか</li></ul> |

崩れていた画面は、端末の名前とスクリーンショットを送る。

## 3. 審査員用のテストアカウント

1. 審査員用の Google アカウントを新しく作る（チームの個人アカウントは使わない）。
2. そのアカウントで本番の URL を開き、一度ログインする。
3. オーナーが、[MVPロール設計](mvp-roles.md)の「本番で教師権限を付ける手順」で教師権限を付ける。鍵を登録したクラウドの Claude Code に頼むこともできる。
4. そのアカウントでログインし直し、「教員のホーム」が開くことを確かめる。
5. 受け渡し方（提出物に書くかどうか）は、オーナーが決める。パスワードは、リポジトリ・PR・Issue に書かない。
