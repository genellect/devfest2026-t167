# API と認可

画面は同じオリジンの `/api` を通して、Cloud Run の API（`api/`）を呼ぶ。この文書は、エンドポイントごとの認可・フェーズの条件・エラーの形をまとめる。概要は [README](../README.md#プライバシーとセキュリティ) にある。エンドポイントを変えたら、`web/` の呼び出し、`api/test/integration`、この文書の表を同じ PR で更新する。

## 認証

表の「司会者」（Host）は議論を作った教員、「生徒」（Participant）は参加した学生を指す。役割は議論ごとに `members.role` で決まる。

health以外は有効なGoogle IDトークンとアプリセッションCookieの両方が必要（セッション作成はfresh Google本人認証から行う）。学校管理者は署名済みのschoolAdmin/schoolId claimsで判定する。追加APIの全仕様は[認証とセッション](auth-sessions.md#api-同一オリジン-api-経由)を参照。

画面は下のパスに`/api`を付けて呼ぶ。公開確認URLの`/api/healthz`は、Next.jsがCloud Runの`/health`へ転送する。`/api/health`も使える。Cloud Runの予約パスを避け、API自身のJSONを確認するため。応答の`gemini: "gemini"`は接続先の設定を表す。分析が成功するかは、画面で分析を実行して確かめる。

## Classroom連携

任意の追加許可で、本人のクラス情報をホーム・作成・参加・待機に利用する。通常のGoogleログインの権限やteacher claimは変更しない。

| API | 認証・認可 | 用途 |
|---|---|---|
| `GET /integrations/classroom/courses` | Google本人・有効なアプリセッション | ACTIVEクラスと、そのクラスでの教員／生徒の役割 |
| `GET /integrations/classroom/courses/{クラス}/discussions` | 同上＋クラス所属 | 新規参加できる議論・参加済みの進行中の議論。コード・名簿・非公開意見を含まない |
| `GET /integrations/classroom/courses/{クラス}/roster` | 同上＋Classroom教員 | 名簿の表示名とGoogleの識別子のみ。メールは取得しない |
| `GET /rooms/{部屋}/classroom/roster` | 同上＋部屋Host＋Classroom教員 | 名簿とアプリの参加済み／未参加を照合。共有端末はログインアカウント単位 |
| `POST /rooms` の `classroomCourseId` | Classroomのクラス所属者（教員・生徒とも） | サーバーで確認したクラス名を保存し、ホーム・履歴に再利用 |
| `POST /rooms/join` の `classroomRoomId` | クラス所属 | コードなし参加。`code`との同時指定は拒否。コード・QR経由の新規参加でもクラス所属を検証 |

Googleアクセストークンは`x-google-access-token`で送信し、署名済みFirebaseのGoogle識別子とUserInfoの`sub`を照合する。永続化・ログ出力しない。名簿照合用の`classroomUserId`はSSEから除外する。追加許可が失効したら明示的に再接続する。既存メンバーの再入室と、サーバーがグループを決める部屋の途中参加は通常のコード参加と同じ条件を維持する。Classroomの取得は1人1分60回まで。課題・成績の取得や結果の投稿は行わない。

|---|---|---|---|---|

| `GET /rooms/{部屋}/materials/{資料}/content` | 必要 | 必要 | — | PDFを返す。送信前にも所属と資料の共有状態を確認する。別の部屋・未所属・除外された人には返さない |

Googleのアクセストークンはリクエストとブラウザのタブ内のメモリだけで使い、Firestore・localStorage・ログには保存しない。SSEでは資料のメタデータだけを配信し、PDF本体はAPIから取得する。資料はAI分析には送らない。共有解除後、参加者の資料一覧と開いている閲覧画面を閉じる。すでにダウンロードされた写しを回収する保証はない。

## グループの進み方

部屋の作成では `groups`（1〜12、既定は 1）でクラス内のグループの数を決める。グループが1つなら参加と同時にグループ1に入り、複数なら参加のあとに生徒が自分で選ぶ（`groups/choose`）。グループは先生が一斉に開くのではなく、それぞれのペースで進む：グループ全員の事前意見（`opinion`）がそろうと議論が始まり、生徒のだれかが議論を終える（`groups/end`）と結論の一文（`statement`）に進み、全員の一文がそろうとそのグループだけを分析して `results/group-{番号}` に保存する。休みの人がいるときは、先生が今いるメンバーで始める（`groups/start`）か、今ある回答で結果を出せる（`groups/analyze`）。グループの状態と人数は部屋ドキュメントの `groupState` に入り、本文は含めない。グループの結果の分析は、Gemini の呼び出しを増やしすぎないよう、結果が出たグループは生徒の操作では分析し直さず（先生だけが出し直せる）、グループごとに同時に1つだけ（`jobId` で古い結果を捨てる）、出し直しは前の分析から30秒あける。`progress` は件数だけを返し、本文は返さない。

参加・グループ移動・意見提出・開始/終了の状態確認と更新はトランザクションで行う。議論開始後の移動は受け付けない。新規参加は、1本化した流れでサーバーがグループを決める部屋だけ議論中も受け付け（途中参加）、それ以外の部屋は開始前だけ。既存メンバーの再参加は維持する。途中から参加した人は表示名だけを登録し、声は議論中の話者の推定に加えない。意見・結論・発言の読み書きは独自セッションを検査するAPIへ集約し、直接アクセスはRulesが拒否する。`closed`では回答・録音・グループ操作・分析を受け付けず、実行中だった分析の結果も書き戻さない。

## 議論の録音

議論の録音はグループで1台（チームドキュメント「仕様」F03）。先生は部屋の作成で録音するか（`recording`、既定は録音する）を決め、生徒はグループ全員の同意を画面で確かめてから録音を始める。先生が録音担当を決めていないグループでは、最初に録音を始めた端末が担当になり（`groups/recorder`）、ほかの人の画面には「〇〇さんの端末が録音を担当しています」と出る。議論が終わると、録音している端末が音声（30分・12MBまで）を `groups/recording` に送り、API が Gemini で議論の流れ・よかった場面・見直したい場面・先生向けの提案を出して `results/flow-g{番号}` に保存する。音声は保存しない。同じ呼び出しで、そのグループの事前の意見から論点を最大10個取り出し、録音の中で話されたか（話された論点は最初に触れた時刻）を判定して `results/points-g{番号}` に保存する。事前の意見の本文と持ち主の ID は保存せず、この文書は先生だけが読める（学生には結果を公開したあとも配信しない）。分析はグループごとに1回で、分析中や別の録音の追加送信は `409`（完了済みの同じ録音の再送は保存済みの受領結果を返し、再分析しない）、Gemini の失敗は `503` を返し、画面は端末に残した録音を送り直せる（通信の途切れや混雑などの一時的な失敗は、画面が自動で3回まで送り直す）。端末に残した録音は、分析が終わると消し、送れなかった録音も議論の終了から5分（受付の締め切り）で消す。Gemini の費用を抑えるため、送り直しは失敗から30秒あけ、分析はグループごとに3回まで（`429`）。結果は、チームドキュメント「タブ 14」に合わせて、グループの結果（`results/group-{番号}`・`results/flow-g{番号}`）はそのグループのメンバーと先生だけが、クラス全体の結果（`summary`・`coverage`）は先生だけが読める（API配信の認可）。

## 結果の整合性

分析が重なっても、遅れて返っても、古い結果が新しい結果を上書きしない。

| 仕組み | 防ぐこと |
|---|---|
| 分析の開始時に、トランザクションで jobId と開始時刻を書く | Cloud Run が複数台になったときの分析の二重実行 |
| 結果の保存時に jobId を照合し、一致しなければ捨てる | 遅れて返った古い分析が、新しい結果を上書きすること |
| 同じ分析は30秒以内にやり直さない（`429` と残り秒数） | Gemini の費用の急増と、画面の連打 |
| 合意の分析で、範囲外・重複した番号を直し、どこにも入らない一文は単独のまとまりにする | 同じ入力で失敗し続けることと、一致度を高く見せること |
| 書き込みは決められた段階で、本人の名義だけ | ほかの学生へのなりすましと、締め切った段階への書き込み |
| Gemini が失敗しても、発言と意見は保存する | AI の障害で議論が止まること |
| 接続先・モデル・設定の値が空なら、起動とデプロイの前に止める | 設定漏れのまま本番に出て、分析だけが失敗し続けること |

## エラー

エラーは `401`（未ログイン）・`403`（所属・役割が違う）・`404`（参加コードや部屋がない）・`409`（フェーズ違い・分析中・処理済み）・`413`（録音が長すぎる・大きすぎる）・`415`（録音の形式）・`429`（30秒以内の再分析・録音の分析の回数の上限）・`503`（Gemini の失敗）で返し、本文は `{ "error": { "code", "message" } }` の形にそろえる。

### 議論中のグループ分析

`POST /rooms/:roomId/analyze` は既存のHost認可・30秒の再実行制限・jobIdによる排他で実行する。従来の未検討論点分析に加え、グループごとの直近20件（各500文字まで）の共有発言メモとテーマだけをGeminiへ渡す。個人名・UID・非公開の事前意見を、このグループ要約の入力には含めない。入力データのグループ番号と照合し、議論の軸（80文字まで）と主な論点（各120文字、3件まで）を `results/live-groups` に保存する。メモがないグループの軸は作らない。

Geminiによる提案には `kind: missing | new_angle` を付ける。未検討の事前意見由来の提案は `missing`。新しい切り口は確定した議論内容と区別し、既存の承認・見送り操作を使う。`live-groups` はHostだけが閲覧でき、結果公開後もParticipantには配信しない。失敗時は503の汎用エラーとし、最後に成功した結果を保つ。古いjobIdや段階変更後の結果は保存しない。追加の構造化Gemini呼び出しは1回にまとめ、モデル・生成設定は変更しない。

履歴（`GET /discussions`）は、所属する議論を作成日時の新しい順に返し、保存されたクラス名も表示に利用する。部屋IDの辞書順を「最近の議論」として扱わない。

2026-11-09の依頼者の最新指示で、teacher claimによる作成・テーマ提案の制限を廃止した。Google認証・有効な独自セッション・利用回数制限は維持し、Host権限は議論ごとのmembers.roleのみで判定する。Classroomの名簿は引き続き同クラスのGoogle教員だけが閲覧できる。
