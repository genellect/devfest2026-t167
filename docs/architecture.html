Topos

構成図：画面・API・データ・AI を Google Cloud のマネージドサービスに分け、ブラウザは同じオリジンの /api だけを呼ぶ

使う人

PC・教室の投影

教員

招待された Google アカウント（teacher claim）。議論を作り、AI の提案を承認するか見送る

スマホ（PWA）

学生

Google でログインし、6桁の数字か QR で参加。事前意見・発言メモ・結論の一文を書く

画面とログイン

Next.js の画面 App Hosting · asia-east1

  • 教員の操作画面と、教室に映す投影画面
  • 学生の画面（ホーム画面に追加できる）
  • /api を同じオリジンで受け、Cloud Run へ転送

Firebase Authentication

学生も教員も Google ログイン。教員は管理側で teacher claim を付けた人だけ

API

Express + TypeScript Cloud Run · asia-northeast1

  • 独自セッション（1人1台）と認可
  • フェーズの進行、分析の排他（jobId）と30秒の間隔
  • 4つの指標の計算
  • 変更のリアルタイム配信（/live）。非公開の本文は本人にだけ

Cloud Firestore asia-northeast1

部屋ごとのサブコレクション。Rules はブラウザからの直接アクセスをすべて拒否し、読み書きは API だけ

AI

Gemini 3.5 Flash Vertex AI · global

  • 事前意見と発言メモを照らし合わせ、まだ話されていない論点を見つける（構造化出力）
  • 結論の一文を、理解のまとまりに分ける
  • 同意を得た録音から、議論の流れを読む（音声は保存しない）

1事前意見収集

2未検討論点の検出

新しい発言メモが届くと、Gemini が事前意見と照合して論点を提案。教員が「全員に表示する」を押したものだけが学生と投影画面に届く

3合意の実態検証

議論のあと全員が結論を自分の言葉で書き、Gemini が理解のまとまりに分けて「同じ結論でも理解が分かれている」ことを示す
