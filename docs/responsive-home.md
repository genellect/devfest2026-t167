# ホーム画面

PCは依頼されたGoogle Driveホームのレイアウトを参考にし、スマホ・タブレットは以前のDiscussモックのGoogle風デザインを使用する。2026-11-08の追加依頼により、実セッション・結果・設定を含む全画面も共通のGoogle風ライトUIへ統一する。

- 学生：`/home`。招待された教員：`/teacher`。教員画面のガードとAPIのteacher claimは維持する。
- ホーム：固定した上部バーと、参加・ホストの2カードだけを表示する。履歴と検索はメニューの「議論の履歴」へ移す。
- 参加：既存JoinFormをモーダルで開き、6桁コードとカメラによるQR読み取りへ接続。Escapeで閉じ、開いたボタンへフォーカスを戻す。
- 検索：取得済みの本人の議論のテーマ・タイトル・クラス名を絞り込む。状況とクラスのフィルターを併用できる。
- データ：実アプリには架空の議論や通知を埋め込まない。クラス名をGET /discussionsに追加し、従来と同じ所属の再検査を通す。非公開の意見や他人のデータは取得しない。

既存のGoogle風ロゴ・イラストを再利用し、Google Driveのスクリーンショットのファイル名・アカウント情報・広告は取り込まない。ホーム固有のレイアウトは専用モジュールに保ち、共通の色・書体・フォーム・カードはboard.cssのMaterial 3スタイルへ統一する。

Docs正本の要件定義・構想・市場／ニーズ・サービス形態・MVPフロー・UIフィードバックとサーバーフィードバック・開発計画・PR手順を確認。新しいフィードバックの「学生と教員のURL分離」「学生に作成を出さない」「コードとカメラで参加」「短い文章」を維持し、見た目は今回の依頼を優先する。PRは作成せず、検査後に指定されたローカル作業場所へ統合する。本番・リモートmainは変更しない。

検証は`bash scripts/dev.sh check`。追加E2Eで履歴の検索・非公開テーマ・削除対象の非表示、参加モーダルのキーボード操作、PC／スマホ／タブレットの表示を確認する。

2026-11-08の依頼者指示により、学生のログイン先をホームに変更し、単独の6桁コード入力ページを廃止した。Docsの旧「学生はコード入力へ直行」より今回の明示指示を優先する。`/join`はホームへの互換転送だけを残し、`?code=...`はホームの参加パネルへ引き継ぐ。通常のホーム表示ではパネルを開かず、QRリンクだけ自動参加を維持する。

参加カード全体を青い参加ボタンにし、下段の「ホストする」は幅50%・同じ高さにした。PCでもこの2つの入口を表示する。全ユーザーに作成画面への入口を表示する今回のUI指示を優先するが、作成画面とAPIのteacher claim認可は維持する。

ホームのメニューは全端末で三本線から開く左側の引き出しに統一した。PCの常時サイドバーは置かない。開く時間は320ms、背景タップ・Escape・項目選択で閉じる時間は400ms。見出しはToposと区切り線で、メニュー内の参加ボタンと閉じるボタンは置かない。参加操作はホームのカードから既存の参加パネルへ引き継ぐ。

参加・ホストの主ラベルは上下左右の中央に配置。両方の高さは216px以上、ホストは参加カードの幅の半分。

引き出しメニューは幅320pxを基本とし、画面幅の80%を上限にする。

上部バーは画面上端に固定し、安全領域・ブラウザ用テーマ色はホームと教員ホームで`#f8fafd`にする。引っ張り更新はブラウザ標準の機能を利用し、独自のタッチ判定・更新表示は置かない。文書全体をスクロールし、ホームでは`overflow:hidden`や`overscroll-behavior`による標準更新の抑止をしない。メニュー表示中だけ背景を固定する。ネイティブ更新UIと引っ張り中のバーの位置は、実機のブラウザによる確認が必要。

参加パネルとホスト画面は400msで下から表示する。ホストへの遷移は、対応ブラウザではホームを背面に残すView Transition、未対応の場合は遷移先のCSSアニメーションを使う。既存の参加入力、認証・教員認可、ローカルのホストモックへの導線は維持する。`prefers-reduced-motion: reduce`では移動アニメーションを省略する。

ローカルのホスト準備は「セッション名」「テーマ」の順。セッション名の初期値は「無題のセッション」、テーマは空で「大学生のうちにすべきアルバイトは？」をプレースホルダーとして表示する。必須・任意のバッジは表示せず、テーマが空白の間は作成ボタンを無効・灰色にする。作成ボタンの高さは従来の1.2倍（PC72px、スマホ67.2px）。右上の×は、対応ブラウザではホームを背面に表示したままホスト画面を400msで下へ閉じる。

通常の作成はテーマ・セッション名のみ。資料選択の固定サンプル画面は提供しない。

ホーム上部の丸い相談バーは、相談入力からテーマ3候補、出し直し、選択テーマをホストフォームへ引き継ぐ。ローカルの候補は既存のGeminiモックを使い、認証・作成の教員認可は維持する。APIの上限と保存方針はREADME「ホームのテーマ相談」を参照。

相談バーを押すとバーの位置から400msで全画面へ広がり、中央に導入、下部に相談入力を表示する。開いた直後は見出しへフォーカスし、入力を押すまでキーボードを開かない。×・Escapeでは逆方向に閉じ、通信を中断して元のバーへフォーカスを戻す。動きを減らす設定では即時に開閉する。入力位置はvisualViewportに追従するが、実機のソフトキーボードとの組み合わせは別途確認する。


マイクの使用はブラウザの許可だけで進み、アプリ内の許可チェックや初回の許可設定は置かない。開始・停止・破棄は利用者が操作し、拒否時には再試行または登録スキップを選べる。


Hostの議論中画面はグループ一覧と全画面詳細を使う。カードを押すと400msで下から開き、戻る・×・Escapeで下へ閉じて元の一覧位置へ戻る。発言率は既存の認可済み配信から取得し、匿名話者・話者不明の分母・10秒更新を維持する。未取得の論点や区間履歴には架空の値を補わず、従来のAI提案・共有・見送りはセッション全体の分析と明示して詳細に置く。終了操作は一覧に1か所だけ置く。終了後のTeacherRoomには既存の発言時間の記録を残す。




### 全画面のライトUI統一（2026-11-08）

ホーム・履歴に加え、実セッションの表示名・音声登録・事前意見・議論・結論・結果、教員の募集・設定・分析、端末管理・プライバシー・認証の画面も同じ配色と書体にそろえる。白と薄いグレー、Googleブルー、丸いボタン、余白あるカードを基本とし、黒板の背景・付箋の傾き・太枠は使わない。board.cssは既存クラスを受ける共通スタイルとして置き換える。tone=board/paperは互換の区分として残す。

共通AppShellと履歴の上部バーは固定し、ResizeObserverで実寸を本文の余白に反映する。文字拡大・タイトルの改行・縦横回転でバーと本文が重ならないようにする。ホームの固定バーと既存の画面遷移・ダイアログ・reduced-motion対応は維持する。書体はRoboto/Noto Sans JPとシステム代替を使い、Googleのロゴやサービス名へ改名しない。

この変更は表示の統一であり、認証・Cookie・権限・API・録音の送信・集計・削除方針・AIの接続先は変更しない。実接続が未完の開発用モックは引き続きモックと表示する。

共有PDFは固定版pdfjs-distでcanvasへ描画し、ページ送りを提供する。worker・フォント・文字マップ・WASMは同一サイトへ生成・配信し、資料を第三者CDNへ送らない。生成物はGitとlintの対象外、依存と生成手順は管理する。
